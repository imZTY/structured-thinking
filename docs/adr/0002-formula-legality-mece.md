# ADR-0002: 公式合法性判定标准——加号两边必须同维度、可构成完整划分

- Status: Accepted
- Date: 2026-10-27
- Deciders: zengtianyi
- Related: ADR-0001

## Context

首次深度访谈后的复盘暴露出 AI 生成框架的一类系统性缺陷：**加号在假装做算术**。典型病灶是 `触达率 = 渠道资源 + 作者势能`——左边是百分比，右边一个是离散资源包、一个是粉丝存量，三样量纲全不同，加起来不可能等于 100%。业内行家一眼就能挑战这种公式（「这两个东西加起来怎么就等于触达率了？」），框架的可信度随之崩塌。更隐蔽的变体还有两种：**嵌套重复计算**（把一个数和它的函数相加）和**受益者混装**（书的角度的指标和作者的角度的指标并排相加）。

## Decision

确立公式合法性判定标准，凡 `+` 连接的公式必须同时满足两条：

1. **同维度**：加号两边的词属于同一个维度（同一量纲、或按同一划分轴切分的同类事物）；
2. **完整划分**：能论述「右边加起来构成左边的完整整体」（互斥且穷尽，或按约定轴的二分/三分）。

不满足任一条，修复方向不是删掉这条公式，而是**把右边改造成与左边同维度**（通常意味着重命名或下移一层）。划分轴的常用选型：按时间（事前/事中/事后）、按受益者（市场/作者）、按形态（货币/非货币）、按来源（渠道/自有）、按可知时间（结果/过程）。

### 乘法的对应标准

`×` 不做算术要求，但只允许两种语义，且须在 note 里写明：
- **真实算术**：`实销册数 = 发货册数 × (1 − 退货率)`，数字真的能算出来；
- **缺一不可的门**：`事前过程 = 签约可行性 × 交付可信度`，任一为零则整体为零。

`÷` 只允许真实算术，且比值须有明确判据（如 `> 1` 才成立）。

## Options Considered

1. **不动公式，只靠 note 解释圆场** —— 否决：note 能救「解释得不够」的公式，救不了「加法本身不成立」的公式；行家挑战的是算式本身，读到 note 之前可信度已经掉了。
2. **要求所有加法都严格 MECE** —— 否决：过严。像 `作者回报 = 版税收入 + 个人品牌杠杆`（货币 + 非货币）按形态二分是完整划分，逻辑 MECE，只是量纲字面不同——判定标准须容纳「按形态/按性质划分」这类合法软量纲，只卡「假装能算出总和」的假硬量纲。
3. **确立「同维度 + 完整划分」双条件 + 修复模式库** —— 选用：条件可操作、可教给后续会话；修复模式（重命名、下移一层、按轴重切）覆盖了本次遇到的全部病灶。

## Consequences

**正面**：
- 后续会话生成/修改公式时有明确的检验清单，AI 生成框架的系统性缺陷有了拦截手段。
- 修复模式库让「发现病灶 → 修哪」有固定路径，不需要每次重新发明。

**负面**：
- 判定仍依赖人工判断（「同一维度」没有机器判据），标准执行有成本。
- 重命名/下移一层会让公式变厚（如 `市场结果 = 实销册数` 这类中间层短公式），树更深一层。

**风险 / 后续行动**：
- 中间层节点因内容标准规则 5（无 expr 不能有 terms）被迫写短公式——这是特性不是 bug，短公式反而让中间层语义更明确，但**不意味着每个中间层都值得展开**，多数时候一层薄包装就够。
- `上市准备 = 首印数 × 书名封面 × 首发资源` 的 `×` 严格说乘不动（首印数是计数不是门），已知豁免未修——若未来有人较真，改法是把首印数改成「首印决策」类门语义。

## Good Cases（真实通过检验的公式）

| 公式 | 为什么站得住 |
|---|---|
| `过程指标 = 事前过程 + 事中过程 + 事后过程` | 按时间轴三分，互斥且穷尽全生命周期 |
| `结果指标 = 市场结果 + 作者回报` | 按受益者二分：市场的裁决 vs 四方之一的作者那份，无包含关系 |
| `触达率 = 渠道触达 + 自有触达` | 两边同为「目标读者中被某来源触达的比例」，同量纲；note 说明两路重叠时按并集计、相加是上界 |
| `书的生命周期 = 首印售罄周期 + 口碑评分` | 按时间二分：首发窗口 vs 长尾 |
| `事前过程 = 签约可行性 × 交付可信度` | 乘法作门：编辑对素人只担心「卖不动、写不完」，任一不过选题会都过不去 |
| `作者回报 = 版税收入 + 个人品牌杠杆` | 软量纲合法案例：按形态二分（一笔钱 + 一份资产），完整划分，note 点明划分轴即可 |
| `MTTR = 感知时间 + 响应时间 + 止损时间 + 定位时间 + 修复时间`（稳定性治理） | 同量纲穷尽加法的标杆：五段同为时长、时间上先后串行、构成恢复全流程 |
| `事中过程 = 感知 × 响应 × 止损`（稳定性治理） | 乘法作门的标杆：任一环为零整体为零，details 还写明了读法（各 90% ≈ 全程做对的概率）与划分边界（定位修复归事后） |
| `监控告警 = 告警覆盖度 × 告警质量`（稳定性治理，2026-10-27 修） | 概念混装节点按链路拆门的修复案例：配不全或全是噪声，事中感知同样归零；顺带展示「无法量化上限时改量化下限」的指标设计思路（应监控点数 = 核心流程 × 5W2H 的下限枚举法） |

## Bad Cases（本次实际修掉的病灶 + 一个 AI 提案的踩坑）

| 坏公式 | 病灶 | 修成 |
|---|---|---|
| `触达率 = 渠道资源 + 作者势能` | **假硬量纲**：左边是率，右边是资源包 + 粉丝存量，加不出百分比 | `触达率 = 渠道触达 + 自有触达` |
| `结果指标 = 实销册数 + 作者回报` | **嵌套重复计算**：`版税收入 = 定价 × 版税率 × 结算册数`，结算册数 ≈ 实销——等于把一个数和它的函数相加 | `结果指标 = 市场结果 + 作者回报`，因果改用 links 表达 |
| `事后过程 = 首印售罄周期 + 口碑评分 + 作者带货占比` | **受益者混装**：月数 + 评分 + 百分比三个单位并列；前两个是书的指标，第三个是作者的筹码 | `事后过程 = 书的生命周期 + 作者筹码`，先按受益者分、再在内部按时间分 |
| `作者势能 = 专栏化选题池 + 视频化分发 + 提前公开`（AI 曾提案，被用户当场否决） | **子项越界跑到兄弟概念的范畴**：专栏化选题池其实是「写作履历/交付可信度」那条腿的东西；视频化分发和提前公开是「建立触达」的做法而非势能的构成。教训：给词写子公式时，先问每个子项是否真属于父词的范畴，而不是属于它的兄弟 | 撤回展开；专栏化内容归位到 `写作履历` 的 note/details，视频化与提前公开挂到改名后的 `自有触达` |
