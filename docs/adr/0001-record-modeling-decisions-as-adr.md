# ADR-0001: 用 ADR 记录认知框架的建模决策

- Status: Accepted
- Date: 2026-10-27
- Deciders: zengtianyi

## Context

structured-thinking 是一个「公式拆公式」的认知框架工具，本仓库的核心资产不是代码，而是 `content/` 下的内容与 `docs/mvp/content-standard.md` 定义的内容标准。2026-10-26 完成首次业内深度访谈（人民邮电出版社编辑白宇）后发现：AI 生成的认知框架在公式结构上有一类系统性缺陷（详见 ADR-0002），而这类「怎么判断一条公式合不合理」的标准，没有地方沉淀——内容标准管数据合法性（能不能进校验器），不管语义合理性（加号两边是不是同一个维度）。

## Decision

在 `docs/adr/` 下用 ADR 记录认知框架的**建模决策与判定标准**：凡是我们踩过的坑、确立的判定规则，都落成一条 ADR，供后续会话（人或 AI）在生成、修改、评审框架时参考。ADR 与内容标准分工：内容标准管机器可校验的合法性，ADR 管人工判断的合理性。

## Options Considered

1. **写进内容标准文档** —— 否决：内容标准是数据格式规范，语义判定标准混进去会混淆「校验器强制」和「人工判断」两种效力层级。
2. **写进各 topic 的 meta 字段** —— 否决：meta 是自由字段，放判定标准会被埋没，且无法跨主题复用。
3. **独立 ADR 目录** —— 选用：决策有上下文、有取舍、有后果，天然是 ADR 形状；且 ADR 的「Accepted 后不改写、推翻就新开一条」纪律正好匹配「标准演化」的诉求。

## Consequences

**正面**：
- 后续会话（尤其是 AI 生成新框架时）有可引用的判定标准，带 Good/Bad Case，get 成本低。
- 标准的演化历史可追溯（哪次访谈推翻了哪条假设）。

**负面**：
- 多一个目录要维护；标准若不常被引用会沦为装饰品。

**风险 / 后续行动**：
- ADR 只对「读过的会话」生效——未来若把判定规则机器化（如 lint 公式量纲），需另立工程任务。
